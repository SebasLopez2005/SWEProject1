# Planned training and progress requirements

**Design draft, November 8, 2026.** The next one-shot generation is on hold. This document records the requested changes and proposed acceptance checks. The [31-story baseline](TRACEABILITY.md) supplies the starting point and the [interface revision](ROUND_02_UI.md) supplies the visual direction.

The main workflow starts with a routine the lifter has already planned. The lifter opens it, sees each prescribed set, records what happened, and marks the set done. Progress comes from completed work rather than from prescriptions.

## Workout plan and execution

| ID | Requirement | Acceptance check |
| --- | --- | --- |
| TR-01 | Create and edit reusable routines with ordered exercises, a set count, rep or time targets, an optional load and unit, an optional target RIR range, and optional rest per exercise. RIR means reps in reserve, the lifter's estimate of how many more reps they could do. A routine can be selected before a workout starts. | Save Bench Press with four sets of 12, target RIR 1–3 and a rest duration. Starting it creates four pending rows. Invalid ranges are rejected. Editing the routine later preserves the plan on already-started and completed sessions. |
| TR-02 | Show each planned set with its target, actual input fields and a **Mark done** action. A set can be pending, done, or skipped. Prefills are suggestions and require confirmation. Allow extra sets and ad hoc workouts for unplanned work. | Enter 11 reps and actual RIR 2 on one bench row. Mark it done and verify the plan still says 12. Skip another row, undo a completion, and finish after confirming how pending rows will be treated. History and analytics contain only confirmed actuals. |
| TR-03 | After completing a working set, start the configured rest countdown when there is another working set in the workout. Allow pause, resume, add time, and skip. A routine can use the workout default or turn automatic rest off. Keep one current countdown on the device. | Complete two sets in sequence and check that only the latest applicable timer runs. Pause and reopen the app, then resume. Editing rest replaces the old alert. Undoing its source completion, finishing, or discarding clears that timer and alert. |
| TR-04 | Provide an optional warm-up block that can include a general movement step and lighter preparatory sets specific to the planned lift. A lifter can edit, complete, or skip each step. | Start a routine with a warm-up, mark one step done, skip another, and proceed to the working sets. The summary identifies the warm-up separately and it contributes zero working sets to goals and muscle scores. |
| TR-05 | Offer optional mobility and stretching by exercise or body area. Include movement instructions and editable rep or duration targets. Dynamic preparation can appear before lifting, with a separate optional post-workout mobility block. | Select a shoulder mobility suggestion for an upper-body routine and open its instructions and timer. Skip or substitute it without changing the programmed lifts. A stretch contributes zero working-set volume. |

A planned session snapshots ordered set targets at start. Each set row has a stable ID, a phase such as warm-up or working, a completion state, and an optional actual result. Weighted sets require confirmed load, unit and reps. Reps-only and timed sets keep their existing field rules. Actual RIR is optional on reps-based work and can differ from the target. Timed mobility uses seconds. An explicit zero load or RIR is a recorded value.

A planned training session can finish after at least one working set is completed. Pending rows require confirmation before finishing and are retained as skipped. The summary can then show planned versus completed counts. Historical routines that contain only exercise lists remain usable, with editable exercise entries and no invented targets. A lifter can save a session as a routine and review its exercise order and targets before saving. Actual load and RIR are copied into new targets only by explicit choice. Confirmed sets and plan state must survive a force-close and sync after reconnecting.

Research supports configurable rest as a useful feature. A trial with 21 trained men found better outcomes for some strength and muscle-size measures with three minutes versus one minute between sets in its protocol. That result informs the option to configure rest. [Schoenfeld et al.](https://pubmed.ncbi.nlm.nih.gov/26605807/)

Warm-up content should help lifters prepare for the next movement. A structured warm-up trial studied injury outcomes in youth football, and stretching evidence varies by technique and context. The app should describe what a step prepares the user to do and avoid promising injury prevention or treating an injury. [Soligard et al.](https://www.bmj.com/content/337/bmj.a2469) · [Behm et al.](https://pubmed.ncbi.nlm.nih.gov/26642915/)

## Catalog and muscle activity

| ID | Requirement | Acceptance check |
| --- | --- | --- |
| TR-06 | Provide a searchable offline exercise catalog with names, equipment, categories, instructions where available, and separate primary and secondary muscle tags. Allow users to add custom exercises and optionally tag their muscles. | Search offline by name, equipment and muscle. Find strength movements, bodyweight movements and stretches. After a catalog refresh, the same stored exercise ID still resolves in prior workouts and routines. |
| TR-07 | Show a front and back body diagram in Profile. Deeper shades indicate greater estimated working-set volume for the selected period. Include a legend, exact totals and an accessible list. Selecting a region shows the exercises and sets that contributed. | Four completed bench sets credit 4.0 set-equivalents to chest and 2.0 each to shoulders and triceps using the example mapping below. A warm-up set and skipped set add zero. Correcting or deleting a completed set updates the diagram and breakdown. |

**Proposed seed.** Free Exercise DB is distributed as JSON under the Unlicense. The inspected revision contains 876 unique exercise records, including 123 stretches. All 876 have at least one primary muscle tag and 604 have secondary tags. The catalog covers common movements and variants. Custom records cover gaps. Bundle a pinned metadata snapshot, map it to local exercise types, and keep the original source identifier and attribution. Review media provenance separately before bundling images. [Free Exercise DB](https://github.com/yuhonas/free-exercise-db) · [Pinned data](https://raw.githubusercontent.com/yuhonas/free-exercise-db/f00c92c7dcf1216a928a52c3706c7ce8e2f71ed5/dist/exercises.json) · [Pinned license](https://github.com/yuhonas/free-exercise-db/blob/f00c92c7dcf1216a928a52c3706c7ce8e2f71ed5/LICENSE.md)

The inspected JSON has SHA-256 `5bb747e3fc658f095a60dcbf6d53c96627acdcc6ffb6fffde86f7e26995d40bf`. Preserve the app's existing exercise IDs and use explicit mappings from imported IDs to old records where the movement variant matches. Retain unknown equipment as unknown. A missing secondary tag means the dataset lists no secondary attribution for that record. [Alternative catalog and licensing terms](https://github.com/rfivesix/OpenExerciseDB/blob/main/LICENSE.md)

**Proposed scoring.** Default to the last 7 calendar days and offer 30 days and a custom range. For each completed working set in a finished session, add 1.0 to each mapped primary region and 0.5 to each mapped secondary region. Collapse duplicate tags per region, with primary taking precedence. Use consistent bands of 0, greater than 0 to under 3, 3 to under 6, 6 to under 10, and 10 or more set-equivalents. Show an outline for zero. Show an unmapped set count when a movement has no usable tags. Label the result estimated training volume by region and explain that it comes from set logs and catalog tags. The fractional method is informed by resistance-training volume research, while the assignment of a particular movement to a region comes from the catalog or a reviewed override. Bench press studies illustrate why attribution can vary with technique. [Pelland et al.](https://pubmed.ncbi.nlm.nih.gov/41343037/?fc=None&ff=20251205061617&v=2.18.0.post22%2B67771e2) · [Saeterbakken et al.](https://pubmed.ncbi.nlm.nih.gov/34198674/)

## Reports, goals and export

| ID | Requirement | Acceptance check |
| --- | --- | --- |
| TR-08 | Provide a monthly report with completed sessions, working sets, weighted volume, lift milestones, and comparison with the preceding month. Label the current month as in progress and compare equivalent elapsed days. Show a clear empty state when data is sparse. | A March workout remains in March after the phone changes time zone. Compare equal elapsed days for an in-progress month, with both comparison windows capped at the shorter available period. Recalculate counts, volume and records when the user edits a session. |
| TR-09 | Let the lifter set a goal for a specific weighted exercise, with target load and unit, a minimum rep count, and an optional deadline. Show the best qualifying logged set, progress to the target, and the workout that achieved it. | For a bench goal of 225 lb × 5, 230 lb × 3 does not meet the goal. A 102.1 kg × 5 working set does meet it. The goal link opens the recorded set. An edited or deleted result recalculates the goal. |
| TR-10 | Add **Export my data** in Profile. Default to the last 30 calendar days, with custom dates and all-time options. Let the user choose workout sets, monthly reports, and optional bodyweight data. Use the system share sheet so they can save files or send them to an analysis tool or AI of their choice. | Export while offline and open the UTF-8 files in a spreadsheet and a CSV parser. One completed set appears once. Original units, plan targets and actual values are distinguishable. Declining to share sends nothing. Bodyweight is included only when explicitly selected. |
| TR-11 | Offer optional bodyweight logging with date, positive weight, and kg or lb. Support editing, deletion, a trend chart, and an optional target weight and date. A lifter can use the app without supplying bodyweight. | Log readings in both units. Switching display units changes the chart presentation and preserves the original values. Editing a reading updates the chart and any bodyweight export. |

Use recorded workout calendar dates for report windows and timestamps for event order. Sum load × reps in a common unit for comparable weighted volume. Show reps-only work and timed work separately. A milestone or goal uses completed working sets for the exact exercise variant. Bodyweight readings and lift weights are distinct. The user's original weight and unit are retained, with a separate normalized value where useful.

Export files should use a stable, versioned schema. `workout_sets.csv` has one row per completed set in a finished workout, with workout date, stable IDs, routine and exercise names, phase, planned reps or duration, target RIR bounds, actual reps or duration, original load and unit, normalized load, actual RIR, and completion timestamp when available. `monthly_progress.csv` contains one summary row per covered month, labelled with date bounds and partial-period status. `bodyweight.csv` is a separate opt-in file. Use ISO dates, consistent decimal separators, empty cells for missing values, correct CSV escaping and spreadsheet formula protection for user-entered text. Exports read only the signed-in user's local records and show whether pending sync may make the view incomplete.

## Reminders and Lock Screen

| ID | Requirement | Acceptance check |
| --- | --- | --- |
| TR-12 | Offer opt-in workout reminders with chosen days and local time, a master switch, and a small rotating set of original goal-related messages. Open today's workout entry point when the notification is tapped. | Schedule one reminder for a chosen day. Completing a workout that day cancels the outstanding reminder when the app learns about the completion. Changing the schedule replaces earlier requests. Denied permission leaves workout logging usable. |
| TR-13 | Show the current workout rest countdown in an iOS Live Activity on supported devices, including on the Lock Screen. Tapping it opens the active workout. A rest-end notification is available with permission. | Start a rest countdown, lock the phone or switch apps, and observe the remaining time advance. After expiration, reopening shows rest complete. Pause, extend and skip reschedule or cancel the previous alert. Finishing or discarding the workout ends its activity. |

Reminders default off. Example original messages include “Have you trained today?”, “Short on time? Start with one planned lift,” and “Log the set that moves you closer to your goal.” Rotate only among enabled messages and avoid duplicate reminders for the same day. Reconcile pending reminders when the app opens, records a workout, changes settings, or receives a synced completion. [Apple local notifications](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app)

Persist the timer state and absolute end time on the device, along with the scheduled notification ID and Live Activity ID where available. A paused timer stores remaining time. The system renders the countdown from the deadline and delivers a scheduled alert independently of a JavaScript loop. On resume, derive the current state from the persisted deadline. Use an in-app countdown with a permitted local alert on devices without Live Activities. An iOS native development build and physical device verification are needed for the Lock Screen behavior, including disabled permissions and recovery after relaunch. [Apple ActivityKit](https://developer.apple.com/documentation/ActivityKit/displaying-live-data-with-live-activities) · [SwiftUI countdown](https://developer.apple.com/documentation/swiftui/text/init(timerinterval:pausetime:countsdown:showshours:)) · [Expo Widgets](https://docs.expo.dev/versions/latest/sdk/widgets/)

## Updated design coverage

- **FW-01–07 and FW-25–28** are modeled in the updated navigation, data and sequences for planned sets, legacy templates, typed actuals, skips and resume. Plan targets belong to routine definitions and session snapshots. Actual values belong to set results.
- **FW-09 and account isolation** extend to routines, snapshots, lift goals, optional bodyweight and synced preferences. Timers and OS request IDs stay on the device that started the rest. Owner-scoped offline writes and explicit conflict handling still apply.
- **FW-11–13** expand from a starter exercise list to the pinned catalog and custom exercises. Catalog categories and muscle metadata are separate from the logging type.
- **FW-14–24 and FW-30–31** are mapped to the report and export contracts for completed work, date windows, units and corrections. Keep the existing analytics for historical working sets. Profile adds the muscle diagram, reports, goals, exports and optional bodyweight.
- **TR-03, TR-12 and TR-13** are covered by the rest and reminder sequences. Verify reminder cancellation, replacement alerts and the locked-phone countdown on native builds.
- Retain the [dark interface requirements](ROUND_02_UI.md). The diagram should pair darker colors with an exact-value list, readable labels and a text legend.

Suggested implementation order once generation resumes: planned sets and routine migration, rest and warm-up, catalog import and muscle view, then reporting, goals, export, reminders, Lock Screen and optional bodyweight.
