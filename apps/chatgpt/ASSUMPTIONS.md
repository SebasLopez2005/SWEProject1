# Implementation decisions

- The frozen design is commit `9dc200da72010ef32dd43b7864c268d2bb058f28`. The professor-reviewed fitness report and its 31 FW stories govern behavior. The Part 1 meal planning and alternate fitness drafts are archived project materials.
- The four lifter personas all use the same account permissions. An instructor exercises their journeys with a demo or regular account. There is no administrator role in the mobile app.
- The app uses Expo Router, React Native, TypeScript, SQLite, and Supabase. SQLite stores each aggregate as an ordered JSON snapshot inside a versioned schema. PostgreSQL validates and projects workout and template entries into relational child tables in the same RPC transaction. Supabase serializes writes per account to order revisions and change events.
- The classroom demo is available in development builds with both Supabase variables unset. It seeds an isolated SQLite partition and displays local save status. A configured development build or a release build uses Supabase Auth and a separate partition for each authenticated account. An optional local Supabase stack exercises the real cloud protocol without hosted credentials.
- A confirmed mutation commits before the interface reports success. The queued snapshot never changes. Its base revision is fixed at first send, so lost responses can be retried with the exact operation envelope. Supabase hashes that envelope in its receipt. The app syncs while active, on reconnection or on explicit retry.
- The report leaves multi-device resolution open. Following the diagrams, workouts keep both versions until review. Keep the server version or retain local work as a separate workout. Finish an active local copy before keeping it alongside an active server workout. Custom exercise and template conflicts can be renamed and rebased. If removing an exercise would leave local references without a valid target, the app asks the user to preserve or clean up those references first.
- Dates represent training calendar days. Weeks start Monday and period presets are 4 weeks, 12 weeks, 1 year and all time. Finite windows include today and mark partial weeks. Backdated workouts omit duration. Graphs use weight × reps for weighted exercises, reps for reps-only exercises, and weekly weighted volume for the overall chart. Timed sets appear in workout and exercise history.
- A set keeps its entered weight and unit. Reports convert using 2.20462 pounds per kilogram and round for display only. Converted input prefills use up to six fractional digits. Use the explicit unit picker to convert an entered value before committing it.
- Templates copy the ordered exercise identities. Archive preserves prior sets and shows archived entries in saved templates. The library and new exercise pickers show active entries by default.
- The source's speed and capacity targets remain proposed benchmarks. The app text setting scales screen content through 200%. The six compact tab captions have fixed typography and retain VoiceOver labels.
- The intended distribution is a signed iOS beta through TestFlight. Android is a source target. Hosted accounts, external tester access, and the instructor's acceptance of TestFlight as the assignment deployment format require separate verification.

- Expo SDK 58 passed the current dependency and Hermes checks. A narrowly matched SDK router development diagnostic is hidden from LogBox while the native smoke test verifies tab navigation. Metro still records it. The runtime also supports manual password entry with autofill disabled to avoid the secure-field reset reproduced during native registration tests.
